# 실시간 퀀트 에이전트 모니터링 및 통합 관리 — 필요한 UI 기능 정리

"실시간 퀀트 에이전트 모니터링 및 통합 관리"를 위해 UI에서 갖춰야 할 기능을 **역할별·화면별**로 정리한 문서다.

**메뉴별·기능별 상세 기획**은 [docs/menu/](menu/README.md) 에서 확인. (대시보드·채팅·백테스트·모니터·지식그래프·설정·공통)

---

## 0. 세션 관련 기획 (상세)

AI 채팅의 **세션(대화 단위)** 은 모니터링·통합 관리의 핵심 객체다. 세션별로 지시·결과·HITL 이력이 구분되므로, 아래 기획을 반드시 반영한다.

### 0.1 세션의 역할

| 항목 | 내용 |
|------|------|
| **단위** | 사용자와 에이전트의 1:1 대화 한 흐름 = 1세션. 세션 ID로 구분. |
| **저장** | 서버(API)에 세션별 메시지·턴·HITL 이력 저장. 목록·조회·삭제·제목 수정 API 제공. |
| **노출** | UI에서는 "대화 목록"으로 보여 주며, 선택한 세션만 채팅 영역에 표시. |

### 0.2 세션 필수 기능 (통합 관리)

| 번호 | 기능 | 설명 |
|------|------|------|
| S-1 | **세션 목록 조회** | 현재 사용 가능한 세션 목록을 제목·수정 시각(또는 상대 시간)과 함께 표시. 최신순 정렬. |
| S-2 | **새 세션 생성** | "새 대화" 등으로 새 세션 생성 후 해당 세션으로 전환, 입력 포커스 부여. |
| S-3 | **세션 전환** | 목록에서 세션 선택 시 해당 세션의 대화 히스토리만 채팅 영역에 표시. |
| S-4 | **세션 삭제** | 세션 단위 삭제. 확인 후 API 호출, 목록·서버에서 제거. (삭제 플로우 상세는 0.5) |
| S-5 | **세션 제목** | 자동: 생성 시 "새 대화", 첫 사용자 메시지 전송 후 해당 내용 요약(또는 앞 N자)으로 갱신. |
| S-6 | **세션 제목 수정** | 사용자가 목록/헤더에서 제목을 직접 수정 가능. (플로우 상세는 0.6) |

### 0.3 세션 목록 UI (항목별 디테일)

| 항목 | 요구사항 |
|------|----------|
| **표시 내용** | 세션 제목(한 줄, 말줄임), 수정 시각(예: "2분 전", "오늘 15:30") 또는 `updated_at` 포맷. |
| **선택 상태** | 현재 열린 세션은 시각적으로 강조(배경색·테두리·굵은 글씨 등). |
| **호버/접근** | 항목 호버 시 삭제 버튼(휴지통 아이콘) 노출. 모바일은 길게 누르기 메뉴에서 "삭제"·"제목 수정" 제공 가능. |
| **제목 수정 진입** | 항목 더블클릭, 또는 항목별 메뉴(⋯) → "제목 수정" 선택 시 인라인 편집 또는 모달로 제목 입력란 표시. |
| **빈 목록** | 세션이 0개일 때 "아직 대화가 없습니다." + "새 대화" 버튼만 표시. |

### 0.4 세션 UI 요구사항 (레이아웃·반응형)

| 구분 | 요구사항 |
|------|----------|
| **가시성** | 세션 목록이 채팅 화면에서 **기본으로 노출**된다. (세션 0개일 때는 빈 상태 + "새 대화" 유도) |
| **레이아웃** | **데스크톱**: **제미니형 3단** — 좌측 = 세션 목록(새 채팅 + 채팅 목록 쭉 나열), 중앙 = 채팅·입력, **우측 = 스킬·도구 목록**(클릭 시 이번 질의에 해당 스킬 강제 사용, 호버 시 상세 툴팁). 세션 목록 = 좌측 사이드바(접기/펼치기 권장). **태블릿/모바일**: 세션 목록 = 드로어 또는 상단 드롭다운으로 열고, 채팅은 전체 너비. |
| **반응형** | 화면 크기에 따라 레이아웃 전환. 한 번에 하나의 컨텍스트(목록 vs 대화)에 집중하는 "앱다운" 체감. |
| **입력 영역** | 채팅 입력창은 하단 고정 또는 스크롤 시에도 접근 가능. |
| **빈/에러 상태** | 세션 없음·로딩·API 실패 시 안내 문구·재시도 노출. |

### 0.5 세션 삭제 플로우 (상세)

| 단계 | 동작 | 비고 |
|------|------|------|
| 1. **트리거** | 사용자가 세션 항목의 삭제 버튼(휴지통 아이콘) 클릭. 또는 항목 메뉴(⋯) → "삭제" 선택. | 삭제 버튼은 호버 시 또는 항상 표시(디자인 선택). |
| 2. **확인** | 확인 다이얼로그(모달) 표시. 문구 예: "이 대화를 삭제할까요? 삭제된 대화는 복구할 수 없습니다." 버튼: "취소", "삭제". | "삭제"는 위험 강조 스타일(예: 빨간색). |
| 3. **취소** | "취소" 클릭 시 다이얼로그만 닫고 아무 변경 없음. | |
| 4. **삭제 실행** | "삭제" 클릭 시 `DELETE /agent/sessions/:id` 호출. 요청 중에는 버튼 비활성화 또는 로딩 표시. | |
| 5. **성공 시** | 목록에서 해당 세션 제거. **삭제한 세션이 현재 열린 세션이었으면**: 다른 세션(예: 목록 첫 번째)으로 전환하거나, 세션이 0개면 빈 채팅 화면 + "새 대화" 유도. | 현재 세션 삭제 시 전환 로직 필수. |
| 6. **실패 시** | 404 등 API 에러 시 토스트/인라인 메시지로 "삭제에 실패했습니다. 다시 시도해 주세요." 표시. 목록은 갱신하지 않음. | 필요 시 재시도 버튼 제공. |

### 0.6 세션 제목 수정 플로우 (상세)

| 단계 | 동작 | 비고 |
|------|------|------|
| 1. **제목 결정 규칙** | **자동 제목**: (1) 세션 생성 직후 = "새 대화". (2) 해당 세션에서 첫 사용자 메시지가 전송되면, 그 내용 앞 N자(예: 50자) 또는 요약을 제목으로 서버에 반영. | 기존 `append` 시 `title` 갱신 로직 활용. |
| 2. **수정 트리거** | 사용자가 세션 항목에서 **더블클릭**, 또는 항목 메뉴(⋯) → "제목 수정" 선택. 또는 채팅 영역 상단(헤더)에 현재 세션 제목을 눌러 편집. | |
| 3. **편집 UI** | **인라인**: 목록 항목이 입력란으로 전환, 기존 제목이 채워진 상태. **또는** 모달/팝오버에 제목 입력 필드(최대 120자), "취소"·"저장" 버튼. | 한 줄 입력, 앞뒤 공백 trim. |
| 4. **저장** | "저장" 또는 Enter 시 `PATCH /agent/sessions/:id` (또는 `PUT`) body `{ "title": "새 제목" }` 호출. 빈 문자열이면 "새 대화" 등 기본값으로 저장. | API 확장 필요: 제목 수정 엔드포인트. |
| 5. **성공 시** | 목록·헤더에 새 제목 즉시 반영. 인라인이면 일반 항목 표시로 복귀. | |
| 6. **취소** | "취소" 또는 Esc 시 편집 취소, 기존 제목 유지. | |
| 7. **실패 시** | 400(길이 초과 등)·404·500 시 "제목 수정에 실패했습니다." 표시, 편집 상태 유지해 재입력 가능. | |

### 0.7 새 세션 생성·전환 플로우 (참고)

| 단계 | 동작 |
|------|------|
| **생성** | "새 대화" 클릭 → `POST /agent/sessions` (body에 `title` 생략 가능) → 응답 `session_id`로 로컬 상태를 해당 세션으로 전환, 채팅 영역 비우기, 입력창 포커스. |
| **전환** | 목록에서 다른 세션 클릭 → `GET /agent/sessions/:id`로 히스토리 조회(이미 캐시돼 있으면 생략 가능) → 채팅 영역에 해당 세션 메시지만 표시, 현재 세션 ID 갱신. |

### 0.8 API 요약 (세션)

| 메서드 | 경로 | 용도 |
|--------|------|------|
| GET | /agent/sessions | 목록 조회 (`id`, `title`, `updated_at`) |
| POST | /agent/sessions | 새 세션 생성 (body `title` 선택) |
| GET | /agent/sessions/:id | 단일 세션 메타·히스토리 |
| DELETE | /agent/sessions/:id | 세션 삭제 |
| **PATCH** | **/agent/sessions/:id** | **제목 수정** (body `{ "title": string }`, 최대 120자) — **명세·구현 추가 필요** |

## 0-2. 대시보드 기획 (현재 포트폴리오)

메인 진입 시 **현재 포트폴리오**와 에이전트·서비스 상태를 한눈에 보여 주는 대시보드가 필요하다. 퀀트 에이전트 모니터링·통합 관리의 요약 화면 역할을 한다.

### 0-2.1 대시보드의 역할

| 항목 | 내용 |
|------|------|
| **목적** | 현재 보유 자산(포트폴리오)·수익 현황·에이전트/스킬 상태·최근 활동을 한 화면에서 파악. |
| **위치** | 앱 네비게이션의 첫 탭(또는 홈). 대시보드 | 채팅 | 모니터 | 설정 중 "대시보드". |
| **데이터** | 포트폴리오는 기존 DB·시뮬레이션·스킬 결과와 연동. 없을 경우 빈 상태·연동 유도 메시지. |

### 0-2.2 현재 포트폴리오 표시 (필수)

| 번호 | 표시 항목 | 설명 | UI 요소 |
|------|-----------|------|---------|
| P-1 | **총 자산 / 평가액** | 현금 + 보유 포지션 평가액 합계. 통화·소수점 자리 정의. | 상단 요약 카드(큰 숫자) |
| P-2 | **현금** | 예수금·미결제 금액 제외한 사용 가능 현금. | 요약 카드 또는 포트폴리오 섹션 첫 줄 |
| P-3 | **보유 포지션 목록** | 종목(심볼)·수량·평균 단가·현재가·평가금액·손익(절대값·%)·비중 등. | 테이블(정렬·스크롤 가능) |
| P-4 | **손익 요약** | 일일/기간 손익, 수익률(%). 실현/미실현 구분 가능하면 표시. | 요약 카드 또는 포트폴리오 상단 |
| P-5 | **Last Update** | 포트폴리오 데이터 기준 시각. 새로고침 버튼으로 재조회. | 카드 또는 섹션 헤더 |

### 0-2.3 포트폴리오 UI 상세

| 항목 | 요구사항 |
|------|----------|
| **레이아웃** | 상단: 요약 카드 2~4개(총자산, 현금, 일손익, 수익률 등). 하단: "현재 포트폴리오" 테이블. |
| **테이블 컬럼** | 종목(심볼)·이름(선택), 수량, 평균 단가, 현재가, 평가금액, 손익(원), 손익률(%), 비중(%). 정렬 가능(클릭 시 컬럼별 오름차순/내림차순). |
| **빈 상태** | 포지션이 0건이면 "보유 포지션이 없습니다." 또는 "연동된 계좌/시뮬레이션에 포지션이 없습니다." 안내. |
| **에러 상태** | 데이터 소스 연결 실패·API 오류 시 "포트폴리오를 불러올 수 없습니다. 새로고침하거나 설정에서 연동을 확인하세요." + 새로고침 버튼. |
| **반응형** | 좁은 화면에서는 카드 세로 쌓기, 테이블 가로 스크롤 또는 카드형 리스트로 전환. |

### 0-2.4 대시보드 추가 섹션 (에이전트·모니터링)

| 섹션 | 내용 | 비고 |
|------|------|------|
| **연결 상태** | API/에이전트 연결 여부(예: 연결됨/끊김). | M-1과 동일. 요약 카드 또는 헤더 |
| **스킬 연결** | 등록된 스킬 목록·상태(가용/에러). | M-2, G-2. 테이블 또는 리스트 |
| **활성 세션** | 현재 세션 수, 최근 활동 시각. | M-4. 카드 또는 숫자 |
| **최근 결정** | 에이전트가 최근 실행한 스킬·세션·결과 요약·시각. | D-1. 테이블, 상세는 모니터 탭으로 |

### 0-2.5 데이터·API (포트폴리오)

| 항목 | 내용 |
|------|------|
| **데이터 소스** | 기존 시뮬레이션·DB·또는 스킬(예: `get_portfolio`, `get_positions`) 호출 결과. 초기에는 스킬/API로 포트폴리오 조회 엔드포인트 제공. |
| **API 제안** | `GET /agent/portfolio` 또는 `GET /portfolio` — 응답: `{ total_asset, cash, positions: [{ symbol, name?, qty, avg_price, current_price, value, pnl, pnl_pct, weight_pct? }], pnl_today?, updated_at }`. |
| **새로고침** | 사용자 새로고침 버튼 클릭 시 해당 API 재호출, 로딩 표시 후 카드·테이블 갱신. |

### 0-2.6 선택(Could) 기능

| 항목 | 내용 |
|------|------|
| **차트** | 자산/수익률 추이 미니 차트(일봉·기간 선택). |
| **종목 클릭** | 포지션 행 클릭 시 해당 종목 상세·뉴스·스킬 호출(예: RSI 조회)로 이동 또는 모달. |
| **필터/검색** | 포지션 테이블 종목명·심볼 검색, 손익 기준 필터(수익/손실만 보기). |

### 0-2.7 요약

- **대시보드** = **현재 포트폴리오**(총자산·현금·포지션·손익) + **에이전트 상태**(연결·스킬·세션·최근 결정).

## 4-2. 백테스트 메뉴 기획

에이전트가 사용하는 **지표·스킬**(RSI, 가격 등)을 활용한 **전략**을 **과거 데이터**로 돌려서 수익률·리스크를 검증하는 기능이다. “이 규칙으로 과거에 매매했으면 어땠을까?”를 숫자로 보여 준다. 현재까지의 에이전트(ReAct·스킬·KG) 구조를 고려해 아래처럼 구성하는 것이 좋다.

### 4-2.1 백테스트가 필요한 이유

| 항목 | 내용 |
|------|------|
| **목적** | 에이전트가 참고하는 시그널(예: RSI 매수/매도)이 과거에 얼마나 잘 먹혔는지, 리스크(낙폭·변동성)는 어땠는지 **숫자로 검증**. |
| **에이전트와의 관계** | 채팅에서 “RSI 30 이하에서 사고 70 이상에서 팔아” 같은 **전략**을 쓰게 되면, 그 전략을 **백테스트 스킬**로도 돌려서 결과만 따로 보고, 전략 개선·비교에 활용. |

### 4-2.2 핵심 기능 제안 (에이전트 연동)

| 번호 | 기능 | 설명 |
|------|------|------|
| B-1 | **기간·종목 선택** | 백테스트할 **기간**(시작일·종료일)과 **종목**(심볼 1개 또는 여러 개, 워치리스트 선택 가능). |
| B-2 | **전략 설정** | 어떤 규칙으로 매수·매도할지. 1단계: **프리셋**(예: RSI 14기간, 30 이하 매수·70 이상 매도) 또는 **지표+임계값** 조합. 추후: 에이전트 대화/KG에서 쓰인 규칙을 “전략”으로 저장해 선택. |
| B-3 | **백테스트 실행** | “실행” 버튼 또는 API 호출 시, 선택한 기간·종목·전략으로 **과거 봉(일봉) 단위** 시뮬레이션. 매수/매도 시점·수익률 계산. |
| B-4 | **결과 요약** | 총 수익률(%), 연환산 수익률, **샤프 비율**(또는 변동성), **최대 낙폭(MDD)**, 거래 횟수, 승률 등 한 화면 요약 카드. |
| B-5 | **거래 내역** | 구체적으로 언제 매수·매도했는지 테이블(일자, 종목, 매수/매도, 가격, 수익 등). |
| B-6 | **수익 곡선** | 기간별 누적 수익(또는 자산 곡선) 차트. (선택) 벤치마크(예: buy & hold)와 비교. |
| B-7 | **에이전트 연동** | 채팅에서 “지난 1년 RSI 30/70 전략 백테스트해줘” → 에이전트가 **run_backtest** 스킬 호출 → 결과 요약을 채팅으로 응답. 상세 결과는 **백테스트 탭**에서 “최근 실행” 목록으로 조회. |

### 4-2.3 UI 구성 (백테스트 탭)

| 영역 | 내용 |
|------|------|
| **위치** | 네비에 **“백테스트”** 탭 추가. (대시보드 | 채팅 | **백테스트** | 모니터 | 설정) |
| **입력 폼** | 기간(시작·종료), 종목(다중 선택 또는 워치리스트), 전략 선택(프리셋/지표+임계값). “실행” 버튼. |
| **결과 영역** | 실행 중: 로딩. 완료 후: 요약 카드(B-4) + 수익 곡선(B-6) + 거래 내역 테이블(B-5). |
| **실행 이력** | (선택) 같은 탭 또는 하단에 “최근 백테스트” 목록(기간·종목·전략·수익률·실행 시각). 클릭 시 해당 결과 다시 표시. |

### 4-2.4 데이터·API

| 항목 | 내용 |
|------|------|
| **과거 데이터** | 백테스트 엔진이 **과거 일봉(또는 분봉)** 가격·지표(RSI 등)를 조회할 수 있어야 함. 기존 퀀트 DB·yfinance·스킬 로직을 “날짜 구간”으로 호출하는 **히스토리 API**가 있으면 재사용. |
| **API 제안** | `POST /agent/backtest` (또는 `POST /backtest`) — body: `{ start_date, end_date, symbols[], strategy: { type: "rsi_threshold", params: { period, buy_below, sell_above } } }`. 응답: `{ total_return_pct, annualized_return_pct, sharpe?, max_drawdown_pct, trade_count, win_rate?, equity_curve?: [], trades: [{ date, symbol, side, price, ... }] }`. |
| **스킬** | `run_backtest` 스킬: 위 API를 내부 호출하고, 결과 요약 문자열을 반환. 에이전트가 채팅에서 “백테스트 해줘” 요청 시 이 스킬을 호출. |

### 4-2.5 에이전트와의 정리

- **스킬 재사용**: `get_rsi_for_ticker` 같은 지표 스킬의 **로직**(또는 과거 데이터용 버전)을 백테스트 엔진에서 기간별로 반복 호출해 시그널 생성 → 매수/매도 시뮬레이션.
- **채팅 연동**: 사용자 지시 → ReAct가 “백테스트가 필요하다” 판단 → `run_backtest` 스킬 호출 → 결과 요약을 채팅으로 전달. 상세는 백테스트 탭에서 확인.
- **(선택) KG 연동**: “이 전략으로 백테스트해봤고 수익률 OO%” 같은 결과를 KG에 기록해, 이후 에이전트가 “비슷한 전략은 과거에 이렇게 나왔어” 참고.

### 4-2.6 우선순위 제안

| 단계 | 내용 |
|------|------|
| **1단계** | 백테스트 **탭** + 기간·종목·단일 프리셋(예: RSI 30/70) 입력 폼 + 실행 API + 결과 요약·거래 테이블. 수익 곡선은 단순 선 그래프. |
| **2단계** | `run_backtest` 스킬 등록 → 채팅에서 “백테스트 해줘” 요청 처리. 결과 요약 응답 + 백테스트 탭에 “최근 실행” 노출. |
| **3단계** | 전략 프리셋 추가·사용자 임계값 입력, 실행 이력 저장·비교, 벤치마크 대비. |
