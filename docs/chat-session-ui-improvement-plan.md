# 채팅 세션·반응형·앱 체감 UI 개선 기획안

**기획 스킬 적용** — 요구사항 정리, 기능 목록, 사용자 스토리, 제약·가정.

---

## 1. 요구사항 요약

| 항목 | 내용 |
|------|------|
| **목표** | 채팅 세션 UI를 여타 AI 서비스처럼 명확히 구분·관리 가능하게 하고, 반응형으로 “앱다운 앱” 체감을 주는 UI로 개선한다. |
| **대상 사용자** | NanoQuant AI를 웹에서 사용하는 퀀트/트레이딩 사용자. 데스크톱·태블릿·모바일에서 동일하게 사용 가능해야 함. |
| **핵심 가치** | 세션 목록이 항상 인지 가능하고, 전환·삭제·새 대화가 직관적이며, 레이아웃이 화면 크기에 맞게 바뀌고, 전체가 한 앱처럼 일관되게 동작한다. |

---

## 2. 기능 목록 (우선순위)

### Must (필수)

- **세션 목록 가시성**: 채팅 화면에서 “새 채팅” 버튼만 보이는 상태를 없애고, **세션 목록이 기본으로 노출**된다. (세션이 없을 때는 빈 상태 메시지 + “새 대화” 유도)
- **세션 목록 UX**: 세션 항목에 **제목(첫 메시지 요약)** + **수정 시각(또는 상대 시간)** 표시. 클릭 시 해당 세션으로 전환, 삭제는 항목별로 명확한 동작(아이콘/버튼).
- **반응형 레이아웃**: 
  - **데스크톱(넓은 화면)**: 세션 목록이 **좌측 사이드바**로 고정 노출(접기/펼치기 가능하면 더 좋음).
  - **태블릿/모바일(좁은 화면)**: 세션 목록은 **드로어(슬라이드)** 또는 **상단 드롭다운**으로 열고, 채팅 영역은 전체 너비 사용. “앱처럼” 한 번에 하나의 컨텍스트(목록 vs 대화)에 집중.
- **앱 체감**: 
  - 전체 레이아웃이 **한 화면 안에 정돈**되어 보이도록(불필요한 빈 공간 최소화).
  - 채팅 입력 영역은 **하단 고정** 또는 **스크롤 시에도 접근 가능**한 형태.
  - 로딩·빈 상태·에러 시 **피드백(스피너, 빈 상태 문구, 재시도)**이 명확함.

### Should (권장)

- **세션 사이드바 접기/펼치기**: 넓은 화면에서 세션 목록을 접으면 채팅 영역이 넓어지고, 펼치면 목록이 다시 보이도록 토글.
- **세션 정렬**: 최신 대화 순 정렬 유지, (선택) “최근 사용” 기준 정렬.
- **빈 상태**: 세션 0개일 때 “아직 대화가 없습니다. 새 대화를 시작하세요.” + 강조된 “새 대화” 버튼.

### Could (선택)

- 세션 검색(제목/내용).
- 세션 이름 사용자 수정.
- PWA(오프라인 캐시, 홈 화면 추가)로 더 “앱다운” 경험.

## 3. 사용자 스토리·시나리오

- **US-1**  
  사용자(데스크톱)로서 **이전 대화 목록을 한눈에 보고** 싶어서, 채팅 탭에 들어가면 **좌측에 세션 목록이 항상 보이고**, 각 항목에 제목과 시각이 표시되어 원하는 대화를 클릭해 전환한다.

- **US-2**  
  사용자(모바일)로서 **작은 화면에서도 세션을 관리**하고 싶어서, **세션 목록을 버튼/메뉴로 열면** 드로어 또는 드롭다운으로 목록이 나오고, 선택 시 해당 세션 채팅이 전체 화면으로 보인다.

- **US-3**  
  사용자로서 **새 대화를 빠르게 시작**하고 싶어서, “새 대화” 버튼이 **목록 상단 또는 눈에 띄는 위치**에 있고, 클릭 시 바로 새 세션이 생성되어 입력 포커스가 채팅 입력창으로 간다.

- **US-4**  
  사용자로서 **불필요한 세션을 정리**하고 싶어서, 세션 항목에 **삭제 버튼(또는 아이콘)**이 있어 클릭 시 확인 후 삭제되고, 목록에서 제거된다.

- **US-5**  
  사용자로서 **화면 크기를 바꿔도** 사용하고 싶어서, 브라우저 너비를 줄이거나 모바일로 접속해도 **레이아웃이 깨지지 않고**, 세션 목록·채팅·입력 영역이 모두 접근 가능하다.

---

## 4. 비기능 요구사항

- **반응형**: 뷰포트 기준(예: 768px, 1024px)으로 레이아웃 전환. 좁은 구간에서는 세션 목록이 채팅과 동시에 보이지 않아도 되며, “목록 열기”로 전환 가능하면 됨.
- **일관성**: 세션 목록·채팅·설정·대시보드가 같은 디자인 톤(다크 테마, 카드, pill)을 유지한다.
- **접근성**: 포커스 순서, 버튼/링크 라벨, 키보드만으로도 “새 대화”·세션 선택·삭제 가능하면 좋음.

## 5. 제약·가정·미정

| 항목 | 내용 |
|------|------|
| **제약** | 기존 API(`GET/POST/DELETE /agent/sessions`, `GET /agent/sessions/:id`) 유지. 세션 제목은 서버에서 첫 메시지 기반으로 설정된 값 사용. |
| **가정** | “앱다운”은 PWA 필수는 아니고, **반응형 + 고정/접근 가능한 입력 영역 + 세션 목록 항상 인지 가능**으로 충족 가능. |
| **미정** | 세션 목록 “접기” 시 기본 상태(펼침/접힘) 저장 여부( localStorage 등). |

## 6. 다음 액션 (구현 시 참고)

1. **채팅 탭**:  
   - 세션 목록을 좌측 사이드바로 두고, **세션이 0개일 때** 빈 상태 문구 + “새 대화” 강조.  
   - 세션 항목: 제목(말줄임) + 시각(또는 “방금”, “n분 전”) + 삭제 아이콘.  
   - 미디어 쿼리 도입: `max-width: 768px` 이하에서는 사이드바를 숨기고, “세션 목록” 버튼(또는 햄버거) 클릭 시 드로어/오버레이로 목록 표시.  
   - 채팅 영역과 입력창이 남는 공간을 채우고, 입력창은 하단 고정 또는 스크롤 시 고정.

2. **공통**:  
   - 앱 전체 컨테이너에 `min-height: 100vh`, 채팅 영역 `flex: 1` 등으로 빈 공간이 과하게 남지 않도록 레이아웃 조정.

3. **(선택)** 사이드바 접기/펼치기 토글(아이콘)과 상태 저장.

이 기획안을 기준으로 디자인·개발 단계에서 반응형과 세션 UI를 구체 구현하면 된다.
